# 寫字施法擴充：所有障礙物與機關都要寫對應的注音

日期：2026-11-11　狀態：使用者已確認方向，並提供全部 37 個注音的筆順圖（PDF）

承接 `2026-11-11-write-to-cast-design.md`（只有裂石要寫 ㄅ）。這次把「寫字」擴充到**所有要用招式處理的障礙物與機關**。

## 名詞（與使用者確認）

- **障礙物**：擋住路或寶箱，用對的招式處理後會消失或打開（裂石、落葉、迷霧、泡泡球、小水壩）。
- **機關**：不擋路，用招式啟動後觸發一件事（鈴鐺、風車、大鼓、乾花）。
- 兩者合稱「招式互動物件」。木門不算：它是被風車打開的，不是直接用招式。

## 已確認的決策

| 項目 | 決定 |
|---|---|
| 範圍 | 所有招式互動物件，執行招式前都要先用手指寫出對應的注音 |
| 要寫哪個字 | **由招式自動決定**：物件需要的招式本來就綁了一個注音，不在每個物件上另外填資料 |
| 家長設定 | 仍是同一個「寫字挑戰」開關，一個管全部；預設開 |
| 判定方式 | 沿用現有規則（照虛線描、依序經過關鍵點、容許 14 單位） |
| 筆順資料 | 照使用者提供的 PDF（《注音練習簿》，每一畫標有編號與箭頭） |

## 驗證用的後門

- `window.__game.writeSymbol('ㄊ')`：直接開那個符號的寫字畫布，不用走到機關。
- `window.__game.STROKES`：筆順資料，端對端測試用它產生滑鼠軌跡，不必在測試裡抄一份座標。

## 資料與程式

- `src/data/strokes.ts`：補上 7 個符號的筆順。
- `src/data/maps.ts`：移除 `MapObj.write` 欄位；新增 `abilityOf(obj)`（物件需要的招式：裂石 blast、落葉與風車 gust、鈴鐺 hum、迷霧 fog、機關物件用它自己的 `ability`）。
- `src/data/monsters.ts`：新增 `castSymbol(ability)`：由招式資料查出綁定的注音。
- `src/scenes/World.ts`：新方法 `castWrite(obj)`：設定開、且該注音有筆順資料時，開寫字畫布；回傳 `false` 就不執行招式。六種互動（裂石、落葉、風車、鈴鐺、迷霧、機關）都在「已學會招式」之後、效果之前呼叫它。
- `src/core/ui.ts`：設定列文字改成「用手指寫出注音才能使用招式機關」。
- `src/main.ts`：`__game` 加上 `writeSymbol`、`STROKES`。

## 測試

- 單元測試：每個符號的每一畫「照著描會過」、「把別畫當這一畫描不會過」、「方向反不會過」（抓資料錯誤）；筆畫數符合上表；`castSymbol` 對每一招都回傳有筆順資料的符號；每個招式互動物件的 `abilityOf` 都對得上有筆順的注音。
- 端對端：機器人預設關掉寫字挑戰；除了裂石 ㄅ，再對鈴鐺（ㄇ，兩畫）開啟，用 `__game.STROKES` 產生軌跡，驗證多筆畫流程；其餘維持關閉。

## 風險

- 座標是估的，可能與圖不完全一致；逐個用 `writeSymbol` 確認。
- 每個物件用招式都要寫字，小朋友重複做可能疲乏；每個物件只會處理一次，頻率不高，且有家長開關。
- 交叉的筆畫（ㄆ、ㄊ、ㄌ）的手指操作未在真機試過。

## 不在範圍

其他 28 個符號的筆順資料（等需要時再補）、木門、NPC 與一般戰鬥的寫字。
