# 回家魔法陣：打倒每一關的頭目後，頭目房間出現魔法陣，單向回主島旅館門口

日期：2026-11-16　狀態：使用者已確認方向（全部關卡含第 0 關、放在頭目房間頭目原本站的位置旁、回主島旅館門口），細節為我的建議，待使用者審閱本文件

## 背景與目標

- 打完頭目後，孩子要走很長一段路（洞窟或島）才回得去主島的旅館。
- 在每一關頭目被打倒之後，頭目旁邊出現一個發光的魔法陣，踩上去就回到那一關主島的旅館門口。
- **規則例外**：AGENTS.md 寫「沒有傳送點，往來靠碼頭／stairs／door」。魔法陣是**單向出口**（只能回主島，不能反過來），用 `stairs` 實作，不是通用傳送點，要在 AGENTS.md 補一句。

## 魔法陣的位置與目的地

- 第 1 關的頭目在島上（`d`），不在洞窟 `dc1`／`dc2`，所以手寫洞窟完全不動。
- 小王（`boss_s1`）不放魔法陣（只有每關最後的頭目）。
- 魔法陣物件：`id: 'circle'`、`kind: 'stairs'`、貼圖 `magic_circle`、`label: '魔法陣'`、`showIf: <頭目旗標>`、`to: <目的地>`。位置：**頭目座標旁邊的一格**，在四個方向（左、右、上、下）中依序挑第一格「可走、沒有其他物件（含頭目寶箱）」的格子，並且要在打倒頭目後走得到。
- 抵達格都已確認要可走、不壓物件（旅館門外一格），沿用 `markArrival`／`visited:<map>` 的既有流程，被打倒送回的規則不變。

## 外觀

- **參考感覺**（使用者提供的圖）：藍白色的同心光環（地上的橢圓環）、一道往上升的光柱、往上飄的光點。
- 新貼圖 `magic_circle`：地板上的橢圓同心光環（寬約 1.5 格＝24 像素、高 1 格，藍白色，環上有一圈小符文點，背景透明，畫在地面深度，蓋住旁邊的地磚也沒關係，不影響走路判定，走路判定仍然只有那一格）；`magic_circle` 兩格畫面（亮度略不同）讓光環呼吸式閃爍。
- 光柱與光點由 World 用 Phaser 圖形疊上去（不是貼圖）：一道從光環中心往上約 2 格高、越往上越淡的藍白色光柱（加法混合，alpha 輕輕脈動），加上幾條往上飄、逐漸變淡的細光點（循環 tween）。`reduceMotion` 開時：光柱靜止、不產生飄動的光點。圖形隨 `refreshObjects` 一併銷毀，不洩漏。
- 風格：像素風，不要太寫實；光柱不能蓋住玩家與頭目寶箱的辨識（深度低於玩家、角色，高於地面）。

## 資料與程式

- `src/data/maps.ts`：`b`、`p`、`d` 各加一個 `circle`（只新增物件，不改地形與既有物件）；`mazeObjects` 的 `boss` 角色旁一併產生 `circle`（依上面的選位規則、`showIf` 為該洞窟的頭目旗標、目的地依洞窟 id 對照表），gc2／xc2／zc2／sc2 自動得到；`mazes.ts` 的內容不能變。
- `src/gfx`：`magic_circle` 貼圖與註冊、圖樣測試；World 的閃爍。
- 旗標與存檔不變（魔法陣是否出現完全由頭目旗標決定）。

## 測試

- 每一關：魔法陣存在、`showIf` 為頭目旗標、位置在頭目旁、可走且不壓其他物件（含頭目寶箱）、打倒頭目後（以該洞窟的能力集合）從入口走得到；目的地地圖存在、抵達格可走、不壓物件、就是旅館門外一格（起始村為 (5,4)）。
- 第 0 關與 `dc1`／`dc2` 除了新增 `circle` 之外沒有任何地形或物件改動（鎖住既有座標）。
- 既有測試（`hub.test.ts`、`layout.test.ts`、`game.test.ts`、各關的 BFS 測試）通過；有凍結物件清單的測試要同步更新並說明。
- 端對端：不新增（加步驟會改變各段的流程，風險大於收益）；`node --check` 即可。
- 手動確認：魔法陣外觀、位置、閃爍。

## 風險

- 第 0 關 `b`、`p` 與 `d` 是手寫地圖，要確認頭目旁的格子可走、沒有被既有物件占用；選位規則不適用時（四個方向都被占）要手動指定並在測試說明。
- 魔法陣讓孩子可以直接回主島，但頭目寶箱要記得先開（魔法陣在寶箱旁邊，不影響開寶箱）；孩子若沒開就走，下次還可以走回洞窟開（寶箱旗標不變）。

## 不在範圍

雙向魔法陣、通用傳送點、第二階段的魔法陣（待第二階段回復時再沿用本做法）。
